## The problem

Every computer architecture student needs MARS, and MARS is a Java desktop
application from another era: you install a JAR, you fight your JDK, and on a
Chromebook or a locked-down lab machine you simply can't. The tooling is a
barrier to a subject that's hard enough already.

## What I built

I led core-engine development on a full MIPS32 toolchain running entirely
in-browser: a lexer, a two-pass assembler covering roughly 50 instructions
plus pseudo-instructions, an FPU, and trap handling. 15,000+ lines of strict
TypeScript, deployed live to production.

## The hard parts

### A time-travel debugger

I architected a clean core/UI split, a pure-TypeScript engine behind a Zustand
store, which made a time-travel debugger possible: rewinding register, FPU,
and memory state through a circular snapshot history. Being able to step
backwards through a program is the single most useful thing you can give
someone learning assembly.

### Correctness under test

I wrote 100+ unit and integration tests in Vitest gating every pull request
through GitHub Actions CI. They caught sign-extension and address-resolution
edge cases across the instruction set, the class of bug that silently
produces wrong answers instead of crashing.

### Keeping the engine pure

Putting the engine behind a store rather than inside the components is why
the debugger, the tests, and the visualizations were all possible without
rewrites. It's the decision the whole project rests on.
